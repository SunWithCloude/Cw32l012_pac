# cw32l012-pac

[![CI](https://github.com/SunWithCloude/Cw32l012_pac/actions/workflows/ci.yml/badge.svg)](https://github.com/SunWithCloude/Cw32l012_pac/actions/workflows/ci.yml)
[![license](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](#license)

**English** | [简体中文](README.zh-CN.md)

A standalone, **zero-dependency** register access layer (PAC) for the
**CW32L012** (ARM Cortex-M0+, 64 KB flash / 8 KB SRAM) from Wuhan Xinyuan
Semiconductor (CMSemicon). Only `core` is used — no `svd2rust`, no vendor SVD,
no C headers.

The register data is transcribed from the vendor's *CW32L012 User Manual*
V1.4 and is byte-for-byte identical to the `pac` module of
[cw32l012-hal](https://github.com/SunWithCloude/Rust_Cw32L012) v0.9.1, where it
was validated on real silicon.

## Why not the `cw32l012_pac` 0.1.1 on crates.io?

That crate is generated by `svd2rust` v0.37.1 from the vendor SVD (published
2026-06-25). The SVD has three defects, corrected here against UM V1.4:

| Item | Upstream PAC | This crate |
|------|--------------|------------|
| `GPIOx_PDR @ 0x0C` | whole `0x08–0x0F` range marked reserved | modelled (UM V1.4 §9.6.3). Only PF3 actually has a pull-down on-die; reset value `0x0000_0008` |
| `IRQ31 = FAULT` | `__INTERRUPTS` array has only 31 entries | complete 32-entry `Interrupt` enum |
| `SYSCTRL.PLL @ 0x28` | leftover from a CW32F-series SVD (L012 has no PLL) | treated as reserved (`_pad0` placeholder) |

## What you get

- Memory map and every peripheral base address (UM table 2-1)
- 21 typed register blocks: `Sysctrl` / `Gpio` / `Flashctrl` / `Uart` / `Spi` /
  `I2c` / `Btim` / `Adc` / `Dac` / `Iwdt` / `Gtim` / `Bgr` / `Lptim` /
  `Halltim` / `Vc` / `VcRef` / `Opa` / `Atim` / `Wwdt` / `Rtc` / `Dma`
- `Rw` / `Ro` / `Wo` register primitives (volatile read / write / read-modify-write)
- Bit-field constant modules (`sysctrl`, `gpio`, `uart`, … 21 in total)
- `Interrupt` enum (IRQ0..31) plus NVIC helpers
  (`enable` / `disable` / `pend` / `unpend`)
- `Peripherals` singleton (`take()` / `steal()`)
- Compile-time layout assertions checked against the official `XXX_TypeDef`
  sizes, mirrored by host-side regression tests in `tests/layout.rs`

## Usage

```rust,ignore
use cw32l012_pac::{sysctrl, Peripherals};

let p = unsafe { Peripherals::steal() };

// Enable the GPIOA clock (AHBEN is KEY-protected)
p.sysctrl.ahben.write(sysctrl::KEY | sysctrl::AHBEN_GPIOA);

// Atomically set PA5
p.gpioa.bsrr.write(1 << 5);
```

As a path dependency next to a checkout of the HAL:

```toml
[dependencies]
cw32l012-pac = { path = "../cw32l012-pac" }
```

## Interrupt runtime

This crate does **not** provide a vector table. Two options:

1. Enable the `runtime` feature of `cw32l012-hal` (vector table + `interrupt!`
   macro); the symbol names (`UART1_irq`, …) are listed in the `Interrupt`
   enum docs;
2. Supply your own startup code and vector table when using this crate alone.

## Verification

- `thumbv6m-none-eabi`: debug + release + `clippy -D warnings` + rustdoc, all
  warning-free; `cargo fmt --check` clean.
- Host tests (`cargo test`) assert register block sizes, base addresses, the
  `GPIOx_PDR @ 0x0C` offset and all 32 interrupt numbers.
- The GPIO output path was verified on a CW32L012 board (register read-back
  matches the manual).
- Register data matches `cw32l012-hal` v0.9.1 (same transcription source).

## Publishing note

The name `cw32l012_pac` is already taken on crates.io by the `svd2rust`
version, so publishing this crate would need a different name (for example
`cw32l012-pac-um`). Path dependencies are unaffected.
